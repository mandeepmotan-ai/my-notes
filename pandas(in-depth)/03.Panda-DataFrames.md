# **DataFrames — Creation & Fundamentals**

### **1. The "Table" of Python**

- A **DataFrame** can be thought of as a collection of Series objects that share the same index.
- primary vehicle for data analysis, allowing for operations across both rows (axis 0) and columns (axis 1).
- **A** *DataFrame is a 2D labeled data structure. While a Series represents a single feature or column, a DataFrame represents a complete dataset. It is structured with an Index (rows) and Columns, where each column can have a different data type (int, float, string, etc.)."*

### **2. Core Components**

- **Index (Axis 0):** The row labels. By default, these are integers starting from 0, but they can be set to strings (e.g., names, dates).
- **Columns (Axis 1):** The column labels. Each column is essentially a Pandas Series.
- **Values:** The underlying data, usually stored as a 2D NumPy array for performance.

## **3. Methods of Creation**

### **A. Using Nested Lists**

When using lists, you typically provide a list of lists (where each inner list is a row) and explicitly define the column names.

- **Pros:** Simple for small, manual datasets.
- **Cons:** Not intuitive for labeled data; requires manual column naming.

### **B. Using Dictionaries**

This is the most common manual method. The dictionary **keys** automatically become **column names**, and the **values** (lists) become the data.

- **Pros:** Column names are built-in; very readable.
- **Cons:** All lists must be of the same length, or Pandas will throw a `ValueError`.

### **C. Using `read_csv` (Production Standard)**

In the real world, data is almost always loaded from external files. `pd.read_csv()` is highly optimized for performance.

### **4. Key Operation: `set_index`**

By default, Pandas assigns a numeric ID (0, 1, 2...) to rows. Often, you want a specific column (like `student_name` or `match_id`) to act as the primary key.

- **`set_index('col_name')`**: Moves a column to the index position.
- **`inplace=True`**: Modifies the existing DataFrame instead of returning a new one.

### **5. Code Reference: Building & Loading DataFrames**

```python
import numpy as np
import pandas as pd

# --- 1. Creation from Lists ---
student_data = [
    [100, 80, 10],
    [90, 70, 7],
    [120, 100, 14],
    [80, 50, 2]
]
# Explicitly passing column names
df_lists = pd.DataFrame(student_data, columns=['iq', 'marks', 'package'])

# --- 2. Creation from Dictionary (Preferred Manual Method) ---
student_dict = {
    'name': ['nitish', 'ankit', 'rupesh', 'rishabh', 'amit', 'ankita'],
    'iq': [100, 90, 120, 80, 0, 0],
    'marks': [80, 70, 100, 50, 0, 0],
    'package': [10, 7, 14, 2, 0, 0]
}
students = pd.DataFrame(student_dict)

# Setting a semantic index
students.set_index('name', inplace=True)

# --- 3. Loading from External CSV ---
# movies: Standard load
movies = pd.read_csv('movies.csv')

# ipl: Standard load

```

### **6. Interview & Best Practices**

- **Dictionary Orientation:** By default, dict keys are columns. If you have a dictionary where keys are intended to be rows, you must use `pd.DataFrame.from_dict(data, orient='index')`.
- **`set_index` vs. `reset_index`:** If you set a column as an index, that column is removed from the "data" part of the DataFrame. To bring it back, use `.reset_index()`.
- **Performance on `read_csv`:** For massive files (GBs), interviewers might ask how to speed up loading.
    - *Answer:* Use `usecols` to load only necessary columns, or `dtype` to specify smaller types (e.g., `int32` instead of `int64`).
- **Heterogeneous Data:** Unlike NumPy arrays, a DataFrame can hold different types, but **within a single column (Series)**, the data type should ideally be uniform for performance.

# **DataFrame Attributes & Inspection Methods**

### **1. The Metadata Layer**

- Attributes are properties of the DataFrame (no parentheses `()`), while methods are functions called on the DataFrame (with parentheses `()`).

**Interview Answer:** *"I start every EDA (Exploratory Data Analysis) by checking `.shape` to understand the dataset size, `.info()` to check for data types and missing values, and `.describe()` for a statistical overview. This identifies immediate data cleaning needs, such as type casting or handling nulls."*

### **2. DataFrame Attributes (The "Properties")**

These provide structural information without performing any computation.

| **Attribute** | **Description** | **Why it matters for Interviews** |
| --- | --- | --- |
| **`.shape`** | Returns a tuple `(rows, columns)`. | First check for data loss after a join/merge. |
| **`.dtypes`** | Returns the data type of each column. | Helps identify "numbers" stored as "strings". |
| **`.index`** | Returns the row labels. | Essential for understanding the primary key. |
| **`.columns`** | Returns an array of column names. | Used for iterating over features. |
| **`.values`** | Returns the data as a 2D NumPy array. | Used when passing data to Scikit-Learn models. |

## **3. Inspection Methods (The "Probes")**

These functions calculate or summarize the internal state of the data.

### **A. The Big Three: `info()`, `describe()`, `sample()`**

- **`.info()`**: The most critical method. It reveals:
    - Total number of entries.
    - Column names and their null counts (identifies missing data).
    - Memory usage (critical for scaling).
- **`.describe()`**: Generates descriptive statistics ($count, mean, std, min, 25\%, 50\%, 75\%, max$).
    - *Pro-Tip:* Use `describe(include='all')` to see statistics for categorical columns as well.
- **`.sample(n)`**: Randomly selects $n$ rows. It is better than `.head()` for spotting issues hidden in the middle of a file.

### **B. Data Quality Checks**

- **`isnull().sum()`**: Returns the count of missing values per column.
- **`duplicated().sum()`**: Returns the count of completely identical rows.

### **5. Interview "Tips**

- **The `inplace` Trap:** Methods like `rename()` return a **copy** by default. If you don't use `inplace=True` or reassign (`df = df.rename(...)`), your changes will be lost.
- **`info()` and Memory:** If an interviewer asks how to optimize a DataFrame that's too large, mention that `info()` shows memory usage, and you would use `.astype()` to downcast types (e.g., `float64` to `float32`).
- **Null vs. Empty String:** Remember that `isnull()` detects `NaN` (Not a Number) or `None`, but it will **not** detect an empty string `""` as a null value.
- **Chaining:** `df.isnull().sum()` is an example of method chaining. `isnull()` returns a boolean DataFrame, and `sum()` then aggregates the `True` values (treated as 1).
